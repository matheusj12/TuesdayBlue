# TuesdayBlue — Frontend Development Specification

## Objective

Build **ONLY the frontend** of an enterprise project management platform called **TuesdayBlue**.

This phase is exclusively focused on creating a production-quality React interface.

Do NOT implement:

- Backend
- API
- Authentication
- Database
- Business Logic
- Server Actions
- WebSockets
- State persistence

Every screen must use mocked data.

The frontend should be completely independent and ready to connect to a future Rails 8 API.

---

# Code Rules

Use Functional Components.

Strict TypeScript.

Reusable Components.

Composition over inheritance.

No duplicated code.

No inline styles.

No business logic.

No API calls.

No backend.

Everything should be ready to integrate later with a Rails 8 API.

---

# Final Goal

Build one of the most beautiful enterprise React frontends ever created.

The interface should look more modern and premium than Monday.com, ClickUp, Jira, Asana and Linear.

Every screen should feel handcrafted, elegant, fast and production-ready.
